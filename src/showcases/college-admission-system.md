一个完整走通「真实数据 → 概率建模 → 决策推荐」链路的高考志愿填报分析与预测系统。志愿填报的本质是**用往年的录取分布估计今年的录取概率**，这个项目把这句话做成了可执行的软件：数据管道接入官方公开发布的投档线日报与征集志愿计划，三年真实数据入库，概率模型给出冲稳保推荐与录取模拟，前端可视化面板让人肉眼就能看懂分布。

## 项目概览

- **FastAPI 后端**：约 1450 行 `main.py` 承载 30+ 端点，SQLAlchemy 管理 13 个数据模型，SQLite 单文件存储，零外部依赖即可启动
- **数据面板**：单文件 SPA（约 3770 行）+ Chart.js，13 个功能页面：院校库、专业库、招生计划、投档线、征集志愿、位次分析、趋势分析、冲稳保推荐、捡漏分析、志愿模拟、选科匹配
- **数据规模**：1100+ 所院校、749 个专业、三年度官方公开数据（2023–2025）
- **测试**：37 项 pytest 覆盖分析规则与 API 合约
- **AI 集成**：内置 Claude Code Skill 插件，把全量 API 变成可以被自然语言调用的工具

## 数据工程：从官方文件到结构化数据集

这个项目最扎实的部分其实是数据管道，而不是算法。招生录取数据的官方载体是**投档线日报（CSV/表格）与征集志愿计划（PDF）**——一年十几个批次、每批次上百条记录、格式逐年漂移，要把它变成可查询的数据集，必须解决三类问题：

1. **多源注册与优先级调度**。爬虫采用注册中心 + 策略模式组织，5 个数据源按优先级排序，同一份数据可以从多个来源交叉验证（`source_url` 标注每条记录出身）
2. **文档解析**。PDF 计划表用 pdfplumber 抽取 + 渲染手段兜底，配一个 OCR runner 处理疑似截图页；解析结果先落 staging 区再入库，出错可重跑
3. **数据溯源**（Data Provenance）。`data_provenance` 表记录每条数据的 table/row/action/字段变更，爬虫与导入操作生成 `source_hash` 做批次追踪——查出一条奇怪的分数，可以直接回溯到它来自哪份原始文件。模拟数据全部显式标注 `source_url=模拟数据`，绝不与真实数据混排

## 概率建模：位次怎么变成录取概率

志愿决策的核心输入其实不是分数，是**位次**。系统围绕位次建了一组互相咬合的统计模型：

- **录取概率**：多年同校历史位次 → 正态化 z-score → 标准正态 CDF 输出概率；不足多年数据时退化到线性比值模型或 sigmoid 单值预测
- **预测管线**（`RatioPredictor`）：逐年比值外推来年录取位次，附带**偏差归因**（`BiasAttributor`）——用招生计划、选科、批次合并等因子解释预测为什么偏高偏低
- **一分一段建模**（`ScoreRankModel`）：分数与位次互转基于官方一分一段表插值，而不是简单分段映射
- **冲稳保分类**：概率输出 + 用户风险意愿（可调 mu 范围）分级为「冲 / 稳 / 保」，再叠加**多年趋势分类**（大小年交替检测）做置信度感知的修正
- 招生计划/录取异常的检测器会捕捉「计划暴涨暴跌」「录取线年际异常」这类信号，喂给捡漏分析

## 政策兼容：批次合并不是 bug，是需求

2025 年起省招生考试机构将本科批次合并（原一本、二本合并为「本科批B段」）。系统在**领域规则层**做了兼容：查询 2023–2024 数据匹配原批次命名，查询 2025+ 数据匹配新批次命名，同一所院校跨年趋势则把两套批次历史拼接成连续曲线。这类「政策逐年变化」是招生数据产品的真实复杂度所在，代码里上升为显式的规则层（`backend/core/rules.py`）而不是散落各处的 if。

## 志愿决策引擎

```text
用户输入位次/分数、选科、城市/院校偏好
        │
        ▼
 ├─ 选科匹配 ──── 专业选考科目要求与用户选科比对
 ├─ 批次/城市过滤 ─ 批次规则 + 省市偏好多级匹配
 ├── 概率计算 ──── 历史位次 → CDF 概率（含预测位次版本）
 ├── 模拟录取 ──── 志愿顺序逐个校验（+ 选科 + 合规校验）
 ▼
冲稳保推荐 / 有价值的捡漏机会 / 逐志愿录取结果与概率标注
```

推荐不是黑盒打分：每个候选院校都给出「概率 + 趋势 + 计划变动」三类证据，前端图表可以查证分数转换、位次分布和历年线差。

## AI 集成：Claude Code Skill

这套系统同时被包装成 **Claude Code Skill 插件**：skill 定义里做了后端 API 状态探测与数据统计校验，让 Claude 能通过自然语言直接调用「查去年某校投档线位次 / 给我 21000 位次的冲稳保方案 / 模拟录取」这类请求——相当于把整个分析引擎作为 LLM 的工具层，检索语言模型擅长的交互与整合，计算交给确定性的统计代码。

## 持续改进中

项目**目前处于维护与收敛阶段**，已知的演进方向：

- **预测模块收敛**：代内先后存在两套学习模块（`learning` 与 `learning_module`），正在把旧模块的接口迁移到新的 RatioPredictor 管线，最终收敛成单一入口
- **数据接入**：数据量庞大且结构复杂，**要做全品类、全年份的完整使用体验，需要接入第三方数据 API 接口**，以脱离对人工文档解析的依赖——这是当前最大的工程瓶颈，也是「维护中」标签的含义
- **时序深化**：ARIMA 基线（pmdarima）已引入但未全量接入推荐链路，计划与比值外推融合成最优混合模型
- **质量项**：一处遗留测试与实现不匹配（`test_recommend_strategy`），待与算法行为重新对齐

## 小结

技术清单：**FastAPI / SQLAlchemy / SQLite / pandas / pmdarima / pdfplumber + BeautifulSoup / Chart.js / pytest / Claude Code Skill**。

这个项目的信念是把志愿填报从玄学变成统计题：数据管道是地基、溯源是护栏、概率模型是引擎，剩下的交给用户在可视化面板上做最终决定。
