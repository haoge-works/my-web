写博客久了，重复出现的操作就值得沉淀成文档。这篇把本站在「贴图」「引用链接」「转载」上的约定汇总一下，也是给自己备忘。

## 一、添加图片的三种方式

| 方式 | 引用写法 | 稳定性 | 适用场景 |
| --- | --- | --- | --- |
| 项目内 `public/images/`（推荐） | `/images/xxx.png` | 随站点部署，永不失效 | 文章配图、截图 |
| 外部图床 | `https://图床域名/xxx.png` | 依赖对方网站，防盗链/删图就挂 | 临时引用 |
| Base64 内嵌 | `data:image/...` | 不丢，但 md 文件暴涨 | 极小图标 |

推荐第一种：图片放 `public/images/`，随 git 提交、随站点部署，浏览器打开永远是你的域名，不欠任何图床人情。

贴图语法就是标准 Markdown：

```markdown
![架构示意图](/images/posts/demo.png)
```

几条自己踩过的规矩：

1. 文件名用英文或拼音，别带中文和空格
2. `alt` 文本认真写——图挂了显示的是它，无障碍也靠它
3. 单图控制在一 MB 内，没有任何压缩管线的静态站，大图会显著拖慢整页
4. 站点有深色模式，透明底 PNG 里的深色内容在黑背景下会看不见，截图尽量带不透明浅底

需要固定尺寸或加边框，行内 HTML 即可：

```html
<img src="/images/posts/demo.png" alt="说明" width="480" />
```

## 二、引用链接的门道

### 外部链接

```markdown
参考 [Vite 官方文档](https://cn.vitejs.dev/)。
```

直接贴裸 URL 也会自动变成链接（渲染器开了 linkify）。

一个细节：本站 Markdown 里的链接默认**在当前标签页打开**，不弹新窗口。要把读者留在自己文章里的时候，这反而是好事；确实需要新标签页（比如引用一堆参考文档）时用行内 HTML：

```html
<a href="https://example.com" target="_blank" rel="noopener noreferrer">外部网站</a>
```

### 站内互链

引用站内文章用「文件名即 URL」的 slug，写绝对路径：

```markdown
前文提到过 [Vue3 + Vite 搭博客](/blog/vue3-vite-blog) 的方案。
```

slug 写错会落到「文章不存在」提示页，发布前值得自查一遍。

## 三、转载文章的规范姿势

frontmatter 里加一个 `source` 字段：

```yaml
---
title: 原文标题
date: 2026-11-03
tags: [转载]
source: https://原文链接
---
```

文章页会自动在标题下方渲染一条标注：「本文转载自 <原文链接>，版权归原作者所有」。原创文章不写 `source` 就不会有标注。所有转载文统一打上 `转载` 标签，以后在列表页一键过滤。

如果自定义一点的署名说明授权方式，可以在正文开头手写引用块：

```markdown
> 本文转载自 [原文标题](https://原文链接)，作者：某某，遵循 CC BY 4.0。
```

最后是版权：确认原文允许转载（CC 协议或作者授权）再转；「禁止转载」的内容只做链接推荐，不搬正文。

## 小结

- 图片放 `public/images/`，路径以 `/` 开头，alt 别偷懒
- 链接默认当前页打开，站外文档类链接用新标签页并带上 `noopener`
- 转载认准 `source` 字段 + 出处署名，尊重原作者

这套约定在更细的 `docs/images.md` 与 `docs/links.md` 里，供本仓库读者查阅。
