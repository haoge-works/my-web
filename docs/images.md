# 图片使用指南

本文面向在 `src/posts/*.md` 里写作时添加图片的所有场景。站内对图片**没有代理处理管线**：Markdown 渲染出 `<img>` 后原样输出，不做压缩、裁剪或懒加载，所以图片体积和来源的选择很重要。

## 一、图片来源怎么选

| 方式 | 引用写法 | 稳定性 | 适用场景 |
| --- | --- | --- | --- |
| **项目内 `public/images/`（推荐）** | `/images/xxx.png` | 随站点一起 git 提交与部署，永不失效 | 文章配图、截图、头像 |
| 外部图床 | `https://图床域名/xxx.png` | 依赖对方网站：防盗链、删图、限速都可能挂图 | 临时引用、第三方素材 |
| Base64 内嵌 | `data:image/png;base64,...` | 不丢，但 md 文件膨胀巨大 | 只适合极小的图标，不推荐 |

## 二、使用 `public/images/`（推荐方式）

目录约定：

```
public/
└─ images/          # 文章配图统一放这里
   ├─ xxx.png
   └─ posts/        # 可按文章再分子目录，避免文件名混乱
      └─ vue3-blog-1.png
```

在正文里引用（以站点根为基准的绝对路径，**开头带 `/`，不要写相对路径 `../`）：

```markdown
![文章架构示意图](/images/posts/vue3-blog-1.png)
```

规则与注意：

1. **文件名用拼音或英文**，避免中文与空格（URL 编码味道重、易出错）；单词间用 `-` 连接。
2. 图片随 `git add` 进入仓库。私人仓库没有公开性顾虑，但注意单文件建议控制在 **1MB 以内**（>500KB 的截图先压一压，拖慢整页加载）。
3. 引用路径以 **站点根**（部署后的域名根）为基准；若以后部署到 `https://用户名.github.io/my-web/` 这类子路径，需把 `vite.config.ts` 的 `base` 改成 `/my-web/`，此时 md 里的 `/images/...` 引用要相应检查。

## 三、写作语法

标准 Markdown 图片语法，`alt` 文本建议认真写（图片挂掉时会显示它，也是无障碍要求）：

```markdown
![alt 说明文字](/images/xxx.png)
```

需要控制大小时可用行内 HTML（站内 md 支持行内 HTML，会原样进 Vue 模板）：

```markdown
<img src="/images/xxx.png" alt="说明" width="480" />
带边框样式同理：<img src="/images/xxx.png" alt="说明" style="border: 1px solid #e6e6e2; border-radius: 8px;" />
```

极简排版约定：图片上下已有段落间距，**不要额外包 `<br>` 或空行堆叠**；居中属于每个图特殊排版，同样用行内 HTML 处理。

## 四、深色模式注意

站点有浅色 / 深色两套主题，图片是全局同一张：

- **透明底 PNG** 在深色背景下，如果图中是深色线条/文字会几乎不可见——截图类尽量带不透明浅色底，或导出为 JPG。
- 需要两套图时，用行内 `<img>` 配合 `dark:` class 的方案暂未接入（目前没有 CSS 变量化的图片滤镜），简单做法是选一张两种背景下都可读的图。

- [ ] 文件名全英文小写 + `-` 连接
- [ ] `alt` 文本完整
- [ ] 引用路径以 `/` 开头
